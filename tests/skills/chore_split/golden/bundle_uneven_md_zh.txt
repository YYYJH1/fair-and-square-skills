## 平局用的随机源与复算

| 项目 | 内容 |
| --- | --- |
| 随机源说明 | 虚构示例：2026 年 11 月 29 日某公开开奖，按官网显示的格式原样抄写 |
| 随机源原文（逐字） | （虚构示例）2026-11-29 某公开开奖号码 02 09 16 23 30 + 05 11 |
| 规则名 | chore_bundle_tiebreak_v1 |
| 每周家务总件数（写进种子，即种子里的 n_slots） | 10 |

| 种子原像（对这段文字取 SHA-256） | {"n_slots":10,"participants":["Coco","大刘","小红","阿明"],"rule":"chore_bundle_tiebreak_v1","source":"（虚构示例）2026-11-29 某公开开奖号码 02 09 16 23 30 + 05 11"} |
| 种子（SHA-256，十六进制） | a255593c1fd876e4de71504dc61e588c135750d505523830544434e72d0b948d |
| 平局顺序（靠前的优先） | 阿明、Coco、小红、大刘 |

规则（事先定好，结果出来后不再改）：每人有件数上限，有人做不了的家务不分给他。在这些限制内选每周总代价最小的分法，再用加起来为 0 的补偿，让每个人按自己填的代价都不想换成别人那份（连同那份的补偿或付出），并且在这样的补偿里让折算后最差的人尽量好。

每周总代价（各人按自己填的代价算）：145.00。折算后每周最差的是 Coco、小红：-40.00。

付出的人把钱放进公用的钱罐，收的人从里面拿：付出合计 20.00，收入合计 20.00，恰好相等，不需要外人出钱。

取整到分后，没有人羡慕别人那份（最大羡慕 0.00）。补偿只向下或向上取到分，加起来恰好是 0.00。

平局规则：总代价最小的分法可能不止一种。家务按名称的码位顺序排好，一件一件地分，每一件给平局顺序里最靠前、并且分给他之后仍能得到一种总代价最小的分法的人。

规则里给了公开随机源，但这次总代价最小的分法只有一种，用不上。

复算平局顺序：① 种子 = 「种子原像」的 SHA-256（UTF-8）。② 第 c 次取数（c 从 0 起）= SHA-256（种子 + c 的 8 字节大端）的前 8 字节，按大端读成整数 x。要取 0 到 n−1 之间的整数时，x 小于 2^64 − (2^64 mod n) 就取 x 除以 n 的余数，否则 c 加 1 重取。③ 名单按码位排序，i 从 n−1 降到 1，每步取一个 0 到 i 之间的整数 j，交换第 i 位和第 j 位，最后得到的就是平局顺序。整个过程不用 random 模块。

## 本结果不包含

- 代价是否如实：脚本只对大家自己填的数做算术，别人看不到你的数，所以无法核对。
- 防策略：这个方法不防策略。知道别人填什么的人，有时能靠谎报代价让自己折算后更划算。
- 家务之间的关系：一个人的代价按件相加。一起做更省力或更费力、和做的先后有关的情形不在模型里。
- 钱和代价按 1 比 1 折算，没有预算上限，也不考虑一个人手里有多少钱。
- 并列的分法：总代价相同的几种分法里，选哪一种按事先定的顺序，不保证对折算后最差的人最好。
- 最差的人是在总代价最小的这一种分法里尽量好，不是在所有分法里最好。换一种总代价更高的分法，最差的人有时反而更好。
- 几周之间：这个方案只算一个典型的周，每周重复，不安排几周之间的轮换。
- 请外人做家务（比如保洁）的费用：不计算，分摊用 bill-split。
- 有人喜欢做的任务：代价不能是负数，喜欢做的任务填 0。
