给组织者：上表写着每个人送给谁。只把各人自己的那一条私信发给本人，不要把上表或它的截图发到群里。运行这个脚本的人（包括这次会话）会看到全表。

复算方法：① 种子 = 「种子原像」的 SHA-256（UTF-8）。② 第 c 次取数（c 从 0 起）= SHA-256（种子 + c 的 8 字节大端）的前 8 字节，按大端读成整数 x。要取 0 到 n−1 之间的整数时，x 小于 2^64 − (2^64 mod n) 就取 x 除以 n 的余数，否则 c 加 1 重取。③ 名单按码位排序，编号 0 到 11。第 t 次试排（t 从 1 起）：接着用同一串取数，对编号 0 到 11 做洗牌（i 从 11 降到 1，每步取一个 0 到 i 之间的整数 j，交换第 i 位和第 j 位），得到排列 s。编号 i 的人送给编号 s(i) 的人。如果没有人送给自己，也没有用到「不能送的方向」，这次试排就合法，立刻停下，它就是结果，否则做下一次试排。最多试 20000 次，超过就报错。整个过程不用 random 模块。

核对：用同样的输入再运行一次这个脚本，输出逐字节相同。礼物交换完之后公布上面的材料，任何人都可以自己重新算一遍。

## 本结果不包含

- 随机源是否真的事先约定、事后无法更改、临场无人能预测：脚本核对不了。这三条只要有一条不成立，就有人能影响结果。
- 名单、方式和不能互送的规则是否在随机源公布前就已冻结：由群里的记录证明，脚本只按输入计算。
- 谁看得到结果：运行脚本的人看到全表，抽法又是公开的，所以有名单、不能互送的规则和随机源原文的人，自己跑一遍也能算出全表。这些材料要等礼物交换完再公布。
- 任意错排允许两个人互送（甲送给乙，乙也送给甲）。不想出现这种情况，就选「一圈传下去」，或者把这两个人登记为不能互送。
