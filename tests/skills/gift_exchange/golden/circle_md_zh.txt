| 种子（SHA-256，十六进制） | b9b77ae6d012ea2b3d34cf83a3e16f4ddf0beb0a6558f5fd5e4f019ca7f50ab0 |

给组织者：上表写着每个人送给谁。只把各人自己的那一条私信发给本人，不要把上表或它的截图发到群里。运行这个脚本的人（包括这次会话）会看到全表。

一圈的顺序：Coco → Yuki → 阿明 → 大刘 → 老王 → 小红 → Coco。

复算方法：① 种子 = 「种子原像」的 SHA-256（UTF-8）。② 第 c 次取数（c 从 0 起）= SHA-256（种子 + c 的 8 字节大端）的前 8 字节，按大端读成整数 x。要取 0 到 n−1 之间的整数时，x 小于 2^64 − (2^64 mod n) 就取 x 除以 n 的余数，否则 c 加 1 重取。③ 名单按码位排序，编号 0 到 5。一个方案给每位送礼人 i 定一位收礼人 r(i)，r 是一一对应的，r(i) 不等于 i，也不在「不能送的方向」里，并且所有人连成一个圈（从任何人出发，走 6 步才回到自己）。④ 把全部合法方案按 r(0)、r(1)、r(2)、…… 从小到大排好，用第 ② 步取一个 0 到 N−1 之间的整数 k（N 是合法方案总数），第 k+1 种就是结果。整个过程不用 random 模块。

核对：用同样的输入再运行一次这个脚本，输出逐字节相同。礼物交换完之后公布上面的材料，任何人都可以自己重新算一遍。

## 本结果不包含

- 随机源是否真的事先约定、事后无法更改、临场无人能预测：脚本核对不了。这三条只要有一条不成立，就有人能影响结果。
- 名单、方式和不能互送的规则是否在随机源公布前就已冻结：由群里的记录证明，脚本只按输入计算。
- 谁看得到结果：运行脚本的人看到全表，抽法又是公开的，所以有名单、不能互送的规则和随机源原文的人，自己跑一遍也能算出全表。这些材料要等礼物交换完再公布。
