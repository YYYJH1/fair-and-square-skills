| 种子（SHA-256，十六进制） | 9e2a519c3d90baa1980cfe2dab5da503d47e53bc5e266afe1c78a76d0fd02ac2 |

没分到：阿明。

方法：概率序列（PS）。把每个时段看成一块可以切开的蛋糕，几个名额就是几块。从时间 0 到时间 1，所有人同时开吃，速度相同，每个人每一刻都吃自己列表里还没吃完的最想要的时段，吃完了就换下一个。每个人吃到每个时段的份额，就是他拿到这个时段的概率。列表里的时段都吃完了，剩下的时间算「没分到」。随后把这张概率表分解成若干种确定的分配（Birkhoff-von Neumann 分解），每一种有自己的概率，再由随机源抽出一种。

抽取方法：种子的计数器流给出一个 0 到 D−1 的随机数（D 是各种分配概率的公分母，见上表）：取第 0 次取数 x，x 小于 2^64 − (2^64 mod D) 就取 x 除以 D 的余数，否则取下一次取数。D 超过 2^64 时，每次连续取 k 个数（k 是满足 D 不超过 2^(64k) 的最小整数），按大端拼成一个整数，再照同样的办法处理。各种分配按表里的顺序，各占「概率乘以 D」个连续的数，随机数落在哪一种里，就用哪一种。

复算方法：① 种子 = 「种子原像」的 SHA-256（UTF-8）。② 第 c 次取数（c 从 0 起）= SHA-256（种子 + c 的 8 字节大端）的前 8 字节，按大端读成整数 x。整个过程不用 random 模块。

核对：把本次的输入连同卡片上的结果（claimed）交给 python3 scripts/slot_lottery.py --verify，一致就退出 0，不一致退出 1。随机源原文请自己到公布处再抄一遍，用 --source 传给它。

## 本结果不包含

- 随机源是否真的事先约定、事后无法更改、临场无人能预测：脚本核对不了。这三条只要有一条不成立，就有人能影响结果。
- 名单、名额数和规则是否在随机源公布前就已冻结：由群里的记录证明，脚本只按输入计算。
- 志愿是否被如实录入：每人在自己的私信里核对。
- 概率序列保证抽签之前没有人羡慕别人的概率分布（随机占优意义下），并且序数有效，但不防策略：知道别人志愿的人，有时能靠谎报志愿拿到更好的概率。抽出来的这一种分配，事后仍然可能有人羡慕别人。
- 没有候补名单：有人放弃名额时怎么办，要在规则消息里事先说好，脚本不管。
