Drawn: Yuki, 小周, 大刘.

Waiting list (if someone gives up, the next name moves up; no new draw): Coco, 小红, 阿明, Mia, 老王.

Recompute: seed = SHA-256 of the canonical JSON (sorted keys, no spaces, UTF-8) of {"n_slots": N, "participants": names sorted by code point, "rule": RULE, "source": SOURCE TEXT}. Draw number c = first 8 bytes, big-endian, of SHA-256(seed + c as 8 big-endian bytes). A uniform integer in [0, n) takes x mod n if x < 2^64 - (2^64 mod n), otherwise the next draw is used. The order is Fisher-Yates over the code-point-sorted names, i from n-1 down to 1, swapping position i with a uniform integer in [0, i].

Check it: give this input together with the claimed result (claimed) to python3 scripts/slot_lottery.py --verify. It exits 0 on a match and 1 otherwise. Copy the source text again from where it was published and pass it with --source.

## Not modeled

- Whether the random source was really fixed in advance, cannot be changed afterwards and could not be predicted: the script cannot check this. If any of the three fails, the result can be steered.
- Whether the names, the slot count and the rules were frozen before the source was published: the group's records show it, the script only computes from the input.
- Moving up the waiting list when someone gives up is the group's convention, not a guarantee of the script.
